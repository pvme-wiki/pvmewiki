# Copy to wiki repair

The reported failure was reproduced on `PvME/Arch-Glacor/AFK Arch Glacor`: the old button reported 18 unresolved media assets and exposed a manual field containing an incomplete visual export. The exporter had only been fully provisioned for the sample ports.

The repair installs verified routes for all 325 current guide articles. `copy-fix-corpus-audit.json` records 325 complete exports, zero unresolved assets, 34,420 inline image occurrences, and every protected original source text node unchanged and in order. This is an export/asset coverage audit, not a claim that all 325 pages have been individually previewed on the destination.

Public native wiki files use the previously captured official-label and image metadata evidence. Approved original PvME image URLs remain unchanged, including ten animated GIFs. All 25 original JPEG/GIF/WebP routes were observed loading in a native unsaved wiki preview; see `copy-fix-extension-proof.json`. Unsupported original image hosts use exact original byte copies with matching source and hosted SHA-256 values. Original URLs remain linked. The mirror reports and immutable original files retain the evidence. No artwork was generated or images recomposed.

The clipboard operation now starts inside the button's click handler, with a promised plain-text Blob that resolves after the current published revision has loaded and converted. This preserves the user activation required by browser clipboard implementations. See [Clipboard.write](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/write) and [ClipboardItem](https://developer.mozilla.org/en-US/docs/Web/API/ClipboardItem/ClipboardItem).

Success says to paste into the wiki source editor. A browser clipboard denial offers a fresh **Copy wikitext** action for the complete prepared result. The optional details label is **Wikitext**. A genuinely unresolved future asset still blocks copying, but no longer exposes incomplete wikitext as a manual workaround. No guide wording was edited.

The stopped corpus publication run remains stopped. This repair changes the standalone site's copy functionality and assets only; destination checks use unsaved userspace previews. No RuneScape Wiki guide, index, template, stylesheet, upload or site configuration is published by this repair.

Normal Chrome reload initially retained the old reader despite deployment. The site's ResourceLoader endpoint now has a content-hashed release path (`load-<hash>.php`), computed from its JS/JSON/CSS files and internally rewritten to `load.php`. A new release changes the startup manifest and stylesheet URLs, while unchanged releases remain cacheable. A query parameter on the base load-script URL would be incorrect because MediaWiki 1.43's browser loader appends its own `?` query. No module rename, browser-storage clearing, or debug URL is required.
